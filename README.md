# fbservo

[Servo](https://servo.org/) (Rust 製のブラウザエンジン) をプロセスに組み込み、ページの絵を
フレームバッファ (`/dev/fb0`) へ直接書く試作。

[fbrowse](../fbrowse) は Chromium の画面を CDP 経由で JPEG として受け取って描くため、
文字がにじみ、遅延も大きい。fbservo は Servo のソフトウェア描画 (Mesa の llvmpipe) の
結果を無圧縮の RGBA で読み出し、そのまま fb0 に書く。X も Chromium も要らない。
JavaScript は Servo 内蔵の SpiderMonkey が動かす。

使い道は Web 検索と勉強用のページを読むこと (動画は扱わない)。fb-server 連携はまだ無い。
これからの順番は [ROADMAP.md](ROADMAP.md) にまとめてある。

## 必要なもの

- Rust 1.88 以上
- clang / libclang (bindgen 用)、cmake、pkg-config
- `libfontconfig1-dev` (Servo のフォント探索が fontconfig を直接リンクする。freetype は同梱版を使う)
- Mesa (EGL・ソフトウェア GL。DISPLAY が無い TTY では EGL surfaceless で動く)
- `/dev/fb0` への書き込み権限 (video グループ)
- `/dev/input/event*` の読み取り権限 (input グループ)。hjkl を押している間だけ流すのに使う。
  無くても動くが、長押しを端末のキーリピートで判断するので、押し始めに 0.2 秒ほど止まる

## ビルドと起動

```bash
cargo build --release      # 初回は依存 (Servo 一式・約 800 crate) のビルドに数時間かかる
./target/release/fbservo https://ja.wikipedia.org/
./target/release/fbservo page.html          # ローカルのファイル
./target/release/fbservo rust 言語           # 検索語は DuckDuckGo で検索
./target/release/fbservo                     # 起動してすぐ URL を入力
./target/release/fbservo --full URL          # tmux の中でも画面全体に描く
```

tmux の中で起動すると、自分のペインに描く (fbrowse の `--auto` と同じ。`--auto` も受け付ける)。

- ペインの移動や大きさの変化 (分割、`resize-pane` など) は 500ms ごとに調べて追いかけ、
  ページもその大きさで組み直す。
- 別のウィンドウやセッションに切り替えたとき、同じウィンドウの別のペインがズームされたときは描くのを止め、
  戻ったらすぐ描き直す。
- ペインが縮んだり動いたりしたときと終了したときは、`tmux refresh-client` で自分の絵の跡を
  端末の文字に描き直してもらう。
- セルの大きさは、画面の大きさを tmux クライアントの行数・列数で割って求める (fbrowse と同じ)。
- `/dev/fb0` は内蔵画面そのものなので、内蔵画面に映っている間だけ描く。内蔵画面に映っているクライアント
  (fbterm の中か、コンソール `/dev/ttyN` で動いているもの) が自分のペインを映していなければ、ほかの
  クライアント (drmterm や ssh) に映っていても隠れているとみなす。tmux の外や `--full` では、起動した
  時点で内蔵画面に映っていなければ描かずに終わる (別の tmux サーバのペインから起動したときなど)。

drmterm (外部モニターの端末) の tmux の中で起動すると、fb0 ではなく drmterm の画面のペインに描く
(fbrowse と同じ。`--full` でもペインを追う)。

- drmterm の共有メモリ (`/dev/shm/drmterm-fb-<uid>`) へ書き、ペインの矩形を申告すると、drmterm が端末の上に重ねる。
- drmterm の中かどうかは、ソケット (`$DRMTERM_OVERLAY_SOCK`、`$XDG_RUNTIME_DIR/drmterm-overlay.sock`) を探し、
  drmterm 上の tmux クライアントがこのペインのセッションを映しているかで決める。
- 升目の大きさは drmterm が教える値を使う。drmterm が別のセッションを映したら、隠れたとみなして矩形を取り下げる。
- drmterm は書いたことを知らせると、次の垂直帰線を待ってから画面へ写す。帰線のまぎわに書くと、わずかな揺れで
  前後どちらの帰線にも転び、スクロールが 1 コマ止まったり飛んだりする。そのため、drmterm が教える DRM デバイスと
  CRTC の番号から外部モニターの帰線の時刻を取り、帰線と帰線の真ん中で書く (教えない古い drmterm では、前のコマから
  決めた間隔をあけて書くだけ)。
- drmterm はフォーカスがある間キーボードを握る (EVIOCGRAB) ので、キーボードを直接読んでも何も届かない。
  押している間だけスクロールするため、drmterm にキーの押下・離上を送ってもらう (`KEYS`)。送らない古い
  drmterm では端末のキーリピートで動くので、最初の 1 歩のあと 0.2 秒ほど止まり、離したあとも少し流れる。
- URL の入力欄を出している間はペインの最下行を、キー一覧を出している間はペイン全体を空けて、端末の文字を見せる。

`.cargo/config.toml` で並列数を 2 に抑え、リンクには lld を使っている
(メモリ 3.7GB のマシンでもビルドできるように)。

## キー操作

fbrowse と同じ配置。

| キー | 動作 |
|---|---|
| `h` `j` `k` `l` | スクロール (毎秒 1000px の一定の速さ。押している間は流れ続け、離すと止まる。短く押しても 60px は進む) |
| `gg` / `G` | 先頭 / 末尾 |
| `f` | リンクヒント。クリックできる要素に 2 文字のラベルが出るので、それを打つとクリックする。1 文字目で合わないラベルは消える。`f` / `Esc` で取消、`Backspace` で打ち直し。入力欄 (`textarea` や文字を打てる `input`) を選ぶと、そのまま入力モードへ入る。開いたページの入力欄に最初からフォーカスが当たっていれば (検索欄など)、選ばなくても入力モードで始まる |
| (入力モード) | キーをそのままページへ送る (`Tab` で次の欄へ移動)。`Enter` はページへ送ってから、`Esc` はそのまま、ノーマルモードへ戻る。fbrowse の `i` は無い |
| `b` / `r` | 戻る / 再読込 |
| `Enter` `Space` 矢印 `PageUp` `PageDown` `Home` `End` | そのままページへ送る (入力欄にフォーカスが無ければ、Space で 1 画面、矢印で少しスクロールする) |
| `+` `-` `0` | ズームイン / アウト / リセット (10% 刻み) |
| `t` | 新しいタブ (端末の最下行に URL・ファイル・検索語を入れる) |
| `]` / `[` | 次 / 前のタブ |
| `x` | タブを閉じる |
| `y` | 今の URL を tmux のペーストバッファへコピー (`prefix+]` で貼り付け) |
| `?` | キー一覧 (何かキーを押すと戻る) |
| `Q` / `Ctrl-C` | 終了。`Ctrl-C` は入力モードやプロンプトの途中でも効く |

fbservo だけのキー: `L` で進む、`O` で今の URL を編集して開く。

`m` (カーソル)、`o` (お気に入り)、`p` (クリップボード)、`T` (タブを別ペインへ) はまだ無い。
押すとログに「まだありません」と出る ([ROADMAP.md](ROADMAP.md))。`M` `P` (mpv)、`s` (撮り直し)、
`d` (直前の入力の削除) は作らない (絵が崩れたら `r` で読み直し、入力は入力モードの `Backspace` で消す)。
キー操作の結果は、ログに `[ui] ...` として出る (絵には何も重ねない)。
URL の入力欄 (`t` `O`、起動時) とキー一覧 (`?`) は端末に出し、その間は絵を止める (uim-fep など端末の IME の
変換中の文字も見える)。

## ログと計測

動作中は端末に何も出さない (出すとページの絵を上書きするため)。Servo のログ、
URL・タイトル・読み込み状態、1 フレームごとの時間は `$XDG_RUNTIME_DIR/fbservo.log` に書く。
hjkl で流している間のフレームには、前のフレームから何 ms あけて出したか (`scroll 33ms` など) も付く。

スクロールキーを押してからその結果を fb0 に書くまでの時間は `[key] 押してから Nms で表示` と出る。
先頭で `k` を押したときのように画面が変わらないキーは、500ms 経ったら数えずに捨てる。
終了すると、ログのパスを表示する。
ページの JS コンソール出力もログに `[console Error] ...` のように残る。

スクロールの滑らかさは、ログの `scroll Nms` (予定の間隔) ではなく、画面に届いたもので測る。
キーの長押しの再現と、外部モニターの垂直帰線と突き合わせる道具は `bench/` にある (`bench/README.md`)。

## 仕組み

```
Servo (DOM / Stylo / SpiderMonkey / WebRender)
   │  SoftwareRenderingContext (Mesa llvmpipe, EGL surfaceless)
   ▼
glReadPixels で BGRA のまま読む (fb0 の XRGB8888 と同じ並び。下の行が先頭)
   ▼
垂直同期を待ち、mmap した /dev/fb0 へ行を逆順にコピー (stride は sysfs から)
```

- 読み出しは Servo の `read_to_image` を使わない。あちらは RGBA で読んで全体を複製し、
  上下を反転するので、fb0 向けの並べ替えまで含めると倍以上かかる。
  BGRA で読めない GL なら、自動で `read_to_image` に戻す。
- 1 フレームの時間 (画面全体): paint 2ms、読み出し 10ms (大半は llvmpipe が描き終わるのを待つ時間)、
  fb0 への転送 2ms。
- fb0 は 1 枚しかなく、書いた端から画面に出る。パネルが走査している途中の範囲に書くと、
  その回の走査では上と下で別のコマが混ざる (ティアリング)。垂直帰線の割り込み (`FBIO_WAITFORVSYNC`) で
  起きてから書くと、CPU が混んでいるときは起きるのが 1〜3ms 遅れ、ペインの上の数十行だけ前のコマが
  残っていた (スクロール中に上側が潰れて見える)。いまは別スレッドで帰線の時刻 (位相) を測り続け、
  EDID の走査タイミング (このマシンのパネルは 798 行・60.004Hz) から走査の位置を計算して、書く範囲の
  下端を走査が通り過ぎてから次の回の走査が上端に来るまでの間 (ペインなら約 2.3ms) に書く (`src/scan.rs`)。
  間に合わなければ次の回まで待つ。最初の位相は Servo を起動する前の静かなうちに測る (起動が 0.13 秒延びる)。
  EDID が読めなければ、これまでどおり割り込みを待ってから書く。`FBSERVO_VSYNC=0` で待たなくなる (比べる用)。
- `hjkl` は毎秒 1000px (Vimium で長押ししたときと同じくらい) で、動き出しも止まる前も同じ速さで
  流す (`src/smooth.rs`)。押している間は流れ続け、離すと止まる。端末からは離したことが分からないので、
  キーボードのデバイス (`/dev/input/event*`) から hjkl の押下と離上を読む (`src/kbd.rs`)。
  流し始めるのは端末から文字が届いたときだけなので、ほかのペインで打ったキーでは動かない。
  読めなければ、端末から文字が届くたびに 60px ずつ足す (長押しの最初に 0.2 秒ほど止まる)。
- 長いページでは Servo (WebRender) が 1 コマ組むのに 20〜25ms かかる (画面の外も含め、
  ページ全体の表示項目を毎コマ調べているためとみられる。単純なページなら 1ms もかからない)。60 コマ/秒に間に合ったり間に合わなかったりすると
  コマの間隔が 17ms と 33ms で揺れてカクカクするので、スクロール中は直近のコマにかかった時間から
  60 / 30 / 20 コマ/秒のどれかにそろえ、1 コマで「速さ × 間隔」だけ進める。
  かかった時間は、前のコマを fb0 に書く時刻まで待つ間も Servo のイベントループを回して、
  次のコマができた時刻を見て測る (Servo の waker が呼ばれた時刻は使えない。アニメーションの
  あるページではタイマーで 8ms ごとに呼ばれ、間隔を広げるほど遅く見えて 20 コマ/秒に張り付いた)。
  決めた間隔に間に合わなかったフレームは、ログに `late +17ms` のように付く。
- 次の分は paint のすぐあとに送り、読み出しと垂直同期を待つ間に Servo に次のコマを組ませる。

- Servo の型は `Rc` なので、すべて 1 スレッドで扱う。Servo が別スレッドから起こしたいときは
  `EventLoopWaker` が pipe に 1 バイト書き、メインループは標準入力とその pipe を `poll` する。
- `notify_new_frame_ready` が来たら `paint` → `read_to_image` → `present` → fb0 に書く。
- 端末 (tmux の時計など) に上書きされても戻るよう、変化が無くても 1 秒ごとに直前のフレームを描き直す。
- tmux のペイン追従は別スレッドで `tmux display-message` を 500ms ごとに呼び、変わったときだけ
  メインループに渡す (tmux の起動を待つ数 ms でキー入力を止めないため)。
- 書き込み先は `FBSERVO_FB` で差し替えられる (動作確認用。サイズは fb0 と同じ前提)。
  キーボードは `FBSERVO_KBD` に `:` 区切りでパスを書くとそこから読む (`input_event` を書き込む FIFO など)。

## Servo への修正 (`vendor/servo-paint`)

`servo-paint` 0.7.0 を `vendor/` に置き、`Cargo.toml` の `[patch.crates-io]` で差し替えている。
変えたのは `webview_renderer.rs` の `scroll_node_or_ancestor_skipping_subpixel` だけ。

- 元の Servo は、スクロールを画面上のその位置にある最も内側のスクロール領域へ先に渡す。
  そのとき、はみ出しが 1px 未満の `overflow: auto` の箱 (ja.wikipedia トップの「ようこそ」の枠など)
  もスクロールできる領域として扱う。
- すると `j` 1 回分がその箱を 0.00002px ほど動かすだけで使い切られ、画面は変わらない。
  先頭で `k` を押すと箱が元に戻るので、次の `j` もまた吸われる。
- 修正版は、スクロールした軸の方向に 1px 以上動ける領域だけを対象にする。
- `testpages/subpixel-overflow.html` で確かめられる。中央の箱の上で `j` `k` を押したとき、
  1 回目から毎回動けば正しい。Servo を上げるときは、パッチを外してこのページで再現するか見る。

| ファイル | 内容 |
|---|---|
| `src/main.rs` | 引数、メインループ、キー操作 |
| `src/engine.rs` | Servo / WebView の生成と操作、waker、delegate |
| `src/fb.rs` | fb0 への書き込み (mmap、垂直同期) |
| `src/term.rs` | 端末の raw モード、キー列の解釈 |
| `src/hints.rs` | リンクヒントの JS と結果の読み取り |
| `src/smooth.rs` | hjkl を一定の速さで流す、スクロール中のコマの間隔 |
| `src/kbd.rs` | キーボードのデバイスから hjkl の押下・離上を読む |
| `src/scan.rs` | 画面の走査の位置を見積もり、ティアリングしない書く時刻を決める |
| `src/tmux.rs` | tmux のペインの位置の追従、内蔵画面に映っているクライアントの判定、ペーストバッファへのコピー |
| `src/drmterm.rs` | drmterm への接続 (共有メモリ、矩形の申告、垂直帰線の時刻、キー操作) |
| `bench/` | スクロールの滑らかさを測る道具 (`bench/README.md`) |
| `CLAUDE.md` | 作業するときの決まり (画面を守る、何を測るか) |
| `vendor/servo-paint/` | 上の修正を入れた servo-paint 0.7.0 (MPL-2.0) |
| `testpages/subpixel-overflow.html` | その修正の確認用ページ |
