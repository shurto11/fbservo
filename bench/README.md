# bench: スクロールの滑らかさを測る

ユーザーの操作と同じ形で動かし、画面に届いたものを数えるための道具。どれもユーザーの
tmux サーバとは別の tmux サーバで fbservo を動かし、内蔵画面 (`/dev/fb0`) には描かない
(`lib.sh` が `FBSERVO_FB` にダミーのファイルを渡す)。cookie などの保存先 (`XDG_DATA_HOME`) も
一時ディレクトリにする。結果は `bench/out/<名前>/` に残る。

| スクリプト | 測るもの | 画面 | ユーザーの drmterm |
|---|---|---|---|
| `hold.sh [keys\|nokeys]` | drmterm の中で j を押し続けたとき、途中で止まらず流れるか、離したらすぐ止まるか | 描かない | そのまま |
| `phase.sh` | fbservo が書く時刻が、外部モニターの垂直帰線から見てどこにあるか (`NOCRTC=1` で帰線に合わせない古い動き) | 描かない | そのまま (帰線の時刻を読むだけ) |
| `monitor.sh` | 本物の drmterm で、外部モニターの更新 1 回ごとに新しいコマがいくつ映ったか、ティアリング | 外部モニター | **止めてもらう必要がある** (動いていたら何もしない) |

## 操作の再現 (`holdkey.py`)

j の長押しは、本物のキーボードと同じ間合いで再現する。押下と同時に 1 文字、250ms 後から
33ms ごとにリピートの文字 (カーネルの既定のキーリピート)、1.5 秒で離す。これを 3 回。
文字は tmux から送り、押下・離上・リピートは別に伝える。

- `hold.sh` / `phase.sh`: 偽の drmterm (`fake_drmterm.py`) が KEY 行で送る
  (本物の drmterm がキーボードを握っているときと同じ経路)
- `monitor.sh`: `FBSERVO_KBD` に渡した FIFO へ input_event で書く (`hold_keys.py`)。
  テスト用の drmterm にはキーボードを開かせないため

tmux send-keys で文字を一定の間隔に送るだけでは、押し続けたことにならない (fbservo は
キーの押下と離上を見て、押している間だけ流す)。

## 数えるもの (`analyze.py`)

- `hold`: 押してから最初のコマ、押している間のコマの最大の空き (1〜2 コマ分を大きく超えたら
  止まって見える)、離してから最後のコマまで
- `phase`: 押している間、帰線から FRAME までの時刻の分布と、drmterm が次の帰線で写すとしたときの
  帰線ごとの新しいコマ数
- `monitor`: 押している間、外部モニターの更新ごとに進んだコマ数 (1 ずつなら滑らか) と、
  上端と下端で別のコマが混ざった回数

fbservo のログの `scroll Nms` は fbservo が決めた予定の間隔で、画面に出た間隔ではない。
数字は機械の状態 (スワップ、ほかの Servo) で変わるので、比べるときは同じ条件で交互に
何回か測る。

## 道具

- `c/vbl.c`: CRTC の垂直帰線を待ち、カーネルが記録した時刻を出す (DRM マスターは要らない)
- `c/modes.c`: CRTC と外部コネクタのモードの一覧
- `c/noinput.c`: テスト用の drmterm に `/dev/input` を開かせない (LD_PRELOAD)

C の道具は、使うときに `bench/bin/` へビルドする (libdrm が要る)。
